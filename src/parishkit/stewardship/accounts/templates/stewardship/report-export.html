{% comment %} The live region is what live-status-v1.js refreshes in place while the export is queued or running (it re-reads this passive page, which never extends the login session). When the file becomes ready while the page watches, the download starts once by itself. Refresh status re-reads the panel (and the campaign-work notice) in place (ui-v1.js, a[data-in-place], #519); a file it finds ready waits for Download, as on an ordinary load, and live-status-v1.js watches a fresh panel that is still pending. Retry export and Cancel export post in place too (form[data-in-place], #519): each view redirects back to this page, whose panel is swapped in. The button is usually gone then, so focus falls back to Refresh status just below (data-in-place-fallback) rather than up to the page heading. A refusal is the fixed error page, which draws no panel, so it is shown whole. Regenerate stays a navigation: it answers with a new export's page. While the export's task is still queued (not yet claimed by a worker), ``wait`` says why it has not started and how long it has waited (#340). {% endcomment %}

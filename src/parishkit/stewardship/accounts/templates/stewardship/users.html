{% extends 'stewardship/admin-base.html' %}{% load i18n stewardship %} {% block title %}{% translate "Users" %}{% endblock %} {% block content %}{% comment %} The Users page (#952; user_views.users, admin-portal spec "Portal user management"). New user above one table of users; each row is one line, a long email or Name cut short with an ellipsis and shown whole in its title (the #952 exception to "Table fit and row height"). The table is an action table (#879): its region (id table.anchor) holds the navigators, the delete form, the table and the confirmation dialog, and is what ui-v1.js redraws from data-refresh-url (this page's address, sort and page included) once a deletion is applied. The delete form holds only its CSRF token and the applied version: users are deleted one at a time, so there is no selection column, and the rows' Sign-in activity forms sit in their cells, outside it. The only Administrator's row has no Delete; the server refuses it anyway. Sign-in activity (#953) posts one recorded Google identity to System logs, never putting it in an address; a user with several identities gets a link to Edit user instead, which lists one button per identity, so rows stay one line. {% endcomment %}

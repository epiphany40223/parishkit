{% extends 'stewardship/admin-base.html' %}{% load i18n static stewardship %} {% block head %}{% endblock %} {% block title %}{% translate "Users" %}{% endblock %} {% block content %}{% comment %} The Users page (#952; user_views.users, admin-portal spec "Portal user management"). New user above one table of users; each row is one line, a long email or Name cut short with an ellipsis and shown whole in its title (the #952 exception to "Table fit and row height"). The table is an action table (#879): its region (id table.anchor) holds the navigators, the delete form, the table and the confirmation dialog, and is what ui-v1.js redraws from data-refresh-url (this page's address, sort and page included) once a deletion is applied. The delete form holds only its CSRF token and the applied version: users are deleted one at a time, so there is no selection column. The reader's own row has no Delete (an Administrator never deletes themselves, Administrator decision 2026-10-11), and neither has the only Administrator's, who is always the reader; the line under the table says why, and the server refuses it anyway. Each row's Email links that user's Timeline (#1866), where the user's sign-ins, actions, role changes and emails are listed. The rows have no Sign-in activity control (Administrator, 2026-10-11): the link above the table opens all sign-in activity in System logs, and Edit user lists one button per recorded Google identity (#953). A change reviewed in the shared review dialog (#750) ends here: New and Edit user return to this page, whose reserved status line above the users table says what was applied and when, and takes focus; Import Ministry leaders redraws both tables in place, and its own line, just above the leaders table where the reader acted, says so instead. Both lines (components/review-outcome.html) sit outside the table regions, so a redraw keeps them. The line under the table counts Ministry leader users who never signed in, across every page (#1593), and is always shown so a redraw moves nothing; the About panel repeats the shared Google Account guidance (google_account_help tag) for the Administrator to pass on; the local laptop environment shows it only when it offers Google sign-in, as the sign-in page does. Last successful sign-in uses the compact parish date format in the browser's time zone (data-compact, date-format-v1.js), as other dense tables do (Administrator, 2026-10-11); the server sorts by the timestamp itself. {% endcomment %}

{% load i18n stewardship %}{% comment %} Turn off debug logging (ADM-13 PR 6b), in the Debug logging tile's details (#1214), after its problems and before its panel content, outside the polled status region so a poll never discards a preview. It is always drawn, and its button follows the polled state: greyed with its reason while no service has debug logging in effect or the switch is set. Its forms post to the System health page itself, which answers with this page; ui-v1.js swaps this region (#debug-off) in place. ``debug_off`` holds the step's result: ``preview`` (a system_health.DebugOffPreview), ``requested`` (the switch just set, or the first one when the confirmation was repeated) or ``refused`` (why the step was refused, with the step-up for a stale sign-in). Allow debug logging again (PR 6c, Testing only) answers in this region too, its result marked ``allow``: ``preview`` is then a system_health.DebugAllowPreview and ``allowed`` the switch it cleared. Without a preview, the buttons are shown in a data-live-mirror-target that the polled region keeps current. The server checks every condition again; greying only helps the reader. {% endcomment %}

{% load i18n stewardship %}{% comment %} One mail schedule row. Each visible field is wrapped in data-schedule-field so ui-v1.js can show only the fields the chosen mail type uses (field_rules, from schedule_forms.FIELDS). The server still reports any value that does not apply, so the script is a convenience, not the only check. The same markup, rendered from the formset's empty form, is the template "Add another schedule" clones. A row not yet saved (the blank last row and every added one) is labelled "New schedule"; a saved row on a page without the table keeps "Schedule N". On Dates and mail schedules a saved schedule's form carries schedule_row (schedule_table.attach, #448): its editor has the id the table row controls and starts closed unless it holds an error or an unsaved change, and a schedule that has already run (data-schedule-past) is never opened. A closed editor still posts its saved values, so the formset is unchanged. Under the email list, data-email-summary is where ui-v1.js describes the chosen email from its option's data- attributes (#446, schedule_forms.email_details): the start of its text, the saved schedules that send it and, on Dates and mail schedules, links to preview, test and edit it (while the campaign admits no test mail, a note saying why in place of the test link, #923). data-schedule-label names this saved schedule (on every page that lists schedules), so the summary can tell whether other schedules share the email. The script adds the summary's id to the list's aria-describedby. {% endcomment %}

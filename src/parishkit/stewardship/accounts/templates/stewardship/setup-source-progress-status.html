{% load i18n stewardship %}{% comment %} Load parish data's live status region (#1354): the result or failure, the plain-language summary, the three parts of the load, each downloaded collection, the saved-record bar and the load's start and last sign of activity. The page and the passive status fragment it polls (?format=status, which never renews idle time) both draw it, and live-status-v1.js swaps in the fresh region while the load is active (data-live-pending), then stops. Only the page passes status_url. The region is not aria-live, since its counts change on every poll: the summary (data-live-announce) is read out by the page's announcer only when it changes. The two times tick forward between polls (time[data-live-since], in the same words as jobs/queue_wait.py's waited_words). The polled copy of the Technical details (template[data-live-mirror]) is put into the page's details, so an open disclosure stays open. The source-load idle renewal is a separate, visible-page POST (ui-v1.js), never this read. A settled region is read once more whenever the page is shown again (data-live-recheck-shown), so a load discarded from another tab (#1353) turns Continue into the "no longer used" status in place. Once the region is settled, its hidden follow-up link re-reads the page's step bar in place (live-status-v1.js), so the steps match the status. Nothing the region draws moves the stage boxes or the lines below them (#1903): the summary shares one grid cell with invisible, aria-hidden copies of every other wording (summary_reserve), so it is as tall as the longest, each collection's status shares a cell with its other wordings so a row never wraps part-way through, and the saved-record bar keeps its space, invisible, until saving starts. Continue is not drawn here: it is in the page's step action row at the bottom (#1968), which the follow-up re-read brings up to date. {% endcomment %}

{% load i18n stewardship %}{% comment %} The ParishSoft refresh schedule editor (#632; admin-portal spec, "ParishSoft refresh schedule settings"), with Basic and Advanced modes (#1122; ui-conventions spec, "Basic and Advanced modes"). The shared toggle (components/editor-mode.html, driven by ParishEditorMode in ui-v1.js) sits at the top; Basic offers a few full-refresh choices, which the page script writes into the Advanced rule rows; Advanced has the rule rows, skip rows and Edit as text. The switch makes sense in both modes, so it sits below them. Rule rows, skip rows, the switch and the mode are posted with the page's other settings; the Basic choices and "Edit as text" only fill rows. The server checks everything: refresh-schedule-v1.js posts the unsaved rows to the read-only check (data-check-url) as typing pauses and puts its answer in the data-schedule-part elements and each row's messages. The line beside Save (integration-settings.html) is the check's only live region, and it also says the problems of the schedule as a whole, so nothing the check draws appears above the rows. The data-*-text attributes are the script's words, translated here. The Edit as text list is a shared time entry field (data-time-entry="list", ui-v1.js), so it shows how it reads as the Admin types, like every other Admin time (#1117); it is not posted. The editor offers full refreshes only: quick updates were removed (#1147), and a stored quick rule is not shown. {% endcomment %}{% with editor=schedule.editor %}

Review changes posts here without a page load (data-review-open, UX conventions "Review dialog", #750): while the answer is prepared the form is inert and busy; an accepted review opens the shared review dialog below with schedule-review.html, whose Apply posts the signed preview to Dates and mail schedules, follows the change and then returns to the list, where the status line says what was applied. A review refused for the values posted keeps the dialog shut: ui-v1.js marks each field, shows the summary and opens the editors the answer opened. Any other refusal (a stale page, sends in progress, a refused Apply) shows inside the dialog. Review changes stays unavailable until the form differs from the saved values (data-require-change): proposed dates are drawn as the fields' values but carry the saved ones (data-saved-value, ScheduleWindow), so the page opens with Review available and reverting the dates makes it unavailable again. A blank added schedule is no change. Its hint keeps its space, so it never moves the page. {% endcomment %}

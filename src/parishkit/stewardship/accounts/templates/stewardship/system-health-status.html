{% load i18n stewardship %}{% comment %} The System health region (ADM-13, #530), shared by the page and the passive status fragment that live-status-v1.js polls every 10 seconds. ``health`` is system_health.SystemHealth. Problems come first, then the six panels in the specification's order. It is not itself a live region: screen readers hear data-live-announce, copied into the page's announcer only when the number of problems changes. Internal names stay out of it; the page's Technical details disclosure, outside the region, lists them. Only the page passes status_url. Every time is shown in the browser's time zone. Nothing here changes from one poll to the next unless the state does, so an unchanged poll leaves the region alone: "Last checked" sits outside it (live-status-v1.js updates it), and how long ago the last backup finished is counted in the browser (time[data-live-since]). Accept this change once sits in the ParishSoft refresh panel, under the refusal, in a [data-live-keep] element that a poll leaves alone once it has contents. The daily limit's resume time is shown only while the 24-hour count is at the limit, as a clock time (it is always within the next 24 hours), with "tomorrow" when it falls on the browser's next calendar day. {% endcomment %}

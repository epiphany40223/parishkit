, put the page's own action buttons (each marked data-bulk-action) first and include this last: the selected count and the Select all / Clear selection button sit after the actions, and each keeps a reserved width (ui-v1.css), so their changing text never moves a button under the pointer or rewraps the bar (#563, #736). The whole group (bar and table) sits inside one element marked data-select-table. ui-v1.js reveals the Select all button, wires it with the header checkbox (data-select-all) and the row checkboxes (data-select-row), shows the selected count, and enables the action buttons only while at least one row is selected. While none is, the reason line below the buttons (data-selection-hint) shows the data-select-table element's data-missing-hint (for example "Select at least one file to delete.") as visible text, and the buttons name it in aria-describedby. The line is always there: once a row is ticked its text is only made invisible, so the bar keeps its height (ui-conventions, Administrator decision B2, 2026-10-10; #879). It re-checks all of this on pageshow (#563). The server validates the selection. Rows can be shown with none selectable (every file in use): their selection cells are empty, and the line then shows the data-select-table element's data-none-hint; without one it stays blank (#1332). Optional: empty_hint is a reason the line shows instead while the table has no rows at all (for example "Nothing to import: ..."); without it the line stays blank then, since the table itself says it is empty. hint_id gives the line a fixed id, so a button the server rendered unavailable can name it in its own aria-describedby (#952). {% endcomment %}{% button type="button" variant="secondary" data-select-all-button hidden %}{% translate "Select all" %}{% endbutton %}

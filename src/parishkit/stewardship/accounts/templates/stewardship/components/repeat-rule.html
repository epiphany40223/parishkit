{% load i18n %}{% comment %} The one repeat rule (#1129, ui-conventions "Schedules"): How often, the days of the week, the monthly choices and the From and Until days, drawn the same way for both mail repeat panels. New scheduled email's Repeat (schedule-repeat-entry.html) and the date-change review's "Repeat a reminder" (schedule-repeat.html) include it, so they cannot drift apart, and one page script (data-repeat hooks, ui-v1.js) expands and checks both. - rule: a RepeatRule form (schedule_entry_views), bound or not. Its fields give every choice and its label, so the two panels offer the same choices in the same order; a bound form also gives the values to draw again. - named: true where the server reads the rule back (New's refused page draws it again). The date-change review's panel only adds rows in the page, so its controls have no name and nothing of the rule is posted. - from_value, until_value: the first From and Until days, the campaign's own calendar dates (never shifted). Left out, the boxes start empty and the script fills them. A rule error is shown at its fields (#1915, UX conventions "Field errors and live checks"): each place it can show has an error line (components/repeat-rule-error.html), reserved where the page's own controls can give the error. From and Until each have one; an error about both (the last date before the first, a span over a year) marks both and is said once, in Until's line. The weekdays' line follows the group, and the day of the month's its box. The page script writes the browser's check there; a refused New draws the server's refusal in the same lines, with each control it marks named by rule.marks (aria-invalid and aria-describedby). {% endcomment %}

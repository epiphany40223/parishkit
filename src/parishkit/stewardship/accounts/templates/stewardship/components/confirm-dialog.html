{% load i18n stewardship %}{% comment %} The shared confirmation dialog of action tables (admin-portal spec, "Row actions and confirmation", #879): a native modal that ui-v1.js opens from a control marked data-confirm-open="" (a row's Delete, or the bulk bar's button for the ticked rows). It never uses confirm(). - title_one / title_many and done_one / done_many are the title and the announcement after success, with {name} (the row's data-confirm-name) or {count} filled in by the script. - body and caution say what the action does and what it cannot undo. - form_id names the table's form: confirming posts its fields (CSRF and any base version) plus the chosen rows, without a page load. - The status line ("Working…") is reserved under the buttons, and a refusal is shown below that, so neither ever moves a button. The dialog is anchored to the top of the window (ui-v1.css), so a growing dialog grows downwards. - fallback names the element that takes focus when the control that opened the dialog is gone (its row was removed). With review=True it is instead the shared review dialog of Admin editors (UX conventions, "Review dialog", #750): a form marked data-review-open="" posts its Review without a page load, and the server's review (a fragment marked data-review-answer, holding the signed preview) is shown in the dialog's body, which scrolls while the title and buttons stay in view. - title names the change and labels the dialog; it takes focus on open, never Apply, so the reader hears what is reviewed first. - apply_url is where Apply posts the signed preview (action=confirm); the answer is the change's status, which the dialog follows. - return_url, when set, is the table page a New or Edit page returns to once the change is applied; without it the page's regions are redrawn in place. Either way outcome_id names that page's reserved status line (components/review-outcome.html), which then says what was applied and when. - fallback is as above. {% endcomment %}{% if review %}

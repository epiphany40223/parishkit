{% endaboutpage %} {% comment %}By Ministry (#1133): every Ministry in the reader's scope, whatever the filters show, since it is how a reader picks one. Each count that is not zero, for a Ministry the reader may follow up, applies that Ministry and request to the worklist in place (data-in-place, its address's fragment naming the table region), and the filters then show them (data-in-place-filters); the view builds the addresses (count_links). It is redrawn with every in-place answer (data-table-sync), so a decision's change shows. A reader with one Ministry gets one line; a long list scrolls in its own box. The ParishSoft and campaign marks are the Administrator's concern; a Ministry leader is not shown them (#1135). It sits above the worklist's filters, not between them and the table (#1684): a count applies filters in place, and the table's height changes with them, so anything below the table would move under the pointer (no layout shift). It is a disclosure, closed by default, whose control sits on the heading's line after About this page, so the worklist's first rows show on a laptop's first screen (#1653); the heading, About and By Ministry sit in a grid (.heading-row) whose first row holds the heading and both controls and whose next rows hold About's help and then the counts, full width, so opening either one moves only what follows the controls' row, never the other control. The disclosure is outside the redrawn section, so a redraw keeps it open or closed, and remember-open-v1.js, loaded straight after it, opens it before the page is drawn when this browser remembers it open, so nothing moves on load.{% endcomment %}

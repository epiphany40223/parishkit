{% load i18n stewardship %}{% comment %} Load ParishSoft data's live status region (#1404 PR 5): the step's one state in a line, then the full refresh's stage boxes (components/stage-boxes.html), then a reserved line for the records checked while loading, or, once loaded, how many Families the campaign has and the data's age. ``load`` is offer (not loaded yet), loading, failed, empty (a full load succeeded but no Families matched, #1587) or loaded. Refresh from ParishSoft draws it in wizard mode (source-refresh.html) from the stepper's facts, with ``families`` and ``as_of`` once loaded; while the load runs, live-status-v1.js polls the run's passive status fragment (?view=load, ``campaign_wizard.load_status``), which draws this same region from the run alone and never renews idle time. The region is not aria-live, since its counts change on every poll: its data-live-announce sentence is read out by the page's announcer (outside the in-place region) only when it changes. Once the run has ended, its hidden follow-up link re-reads the page in place, so the stepper's marks, the action row's Continue and this region's full state (the Family count, or Try again) come in with no reload. Every state draws the same lines and boxes, and the summary line keeps room for its longest wording at every width (ui-v1.css), so the switch from one state to the next moves nothing (no layout shift). When the pressed button's in-place answer leaves no button, the summary line takes focus (data-in-place-focus): it names the new state and is already in view, whereas the region itself, the fallback, could scroll the page to show its bottom edge. {% endcomment %}
